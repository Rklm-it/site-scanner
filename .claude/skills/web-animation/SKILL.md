# Анимация на сайте клиента

Сайт малого бизнеса из Ростова смотрят с телефона, на мобильном интернете, по
дороге. Анимация тут не украшение и не вредительство — она либо подсказывает,
что происходит, либо съедает секунды загрузки и место в выдаче. Разница
целиком в том, **чем** её сделали и **где** поставили.

Порядок такой: сначала решить, нужна ли она в этом блоке (ниже), потом взять
самый лёгкий инструмент, который справляется (лестница ниже), потом проверить
скриптом и глазами.

## Лестница инструментов: ниже — дешевле, начинать снизу

| Чем | Цена | Когда берём |
|---|---|---|
| CSS `transition` + `@keyframes` | 0 КБ | hover, фокус, раскрытие меню, подчёркивание — почти всё |
| CSS + `IntersectionObserver` (~15 строк) | 0 КБ | появление секций при прокрутке |
| `motion` / Framer Motion | ~34 КБ gzip, с `LazyMotion` ~18 | проект на React и нужны выход элемента, `layout`, жесты — `/motion-framer` |
| AOS | ~14 КБ | статическая страница без React, нужны только появления — `/scroll-reveal-libraries` |
| GSAP + ScrollTrigger | ~50 КБ | закрепление экрана (pin), прокрутка-как-таймлайн — `/gsap-scrolltrigger` |
| Magic UI / React Bits | по компоненту | готовый эффектный блок под Tailwind и shadcn — `/animated-component-libraries` |

**Одна библиотека на проект.** GSAP рядом с Framer Motion — это два движка
анимации в бандле ради одного и того же; скрипт это ловит.

**Чего на сайтах клиентов не бывает:** three.js, Spline, Vanta, R3F, PixiJS.
Крутящаяся модель в hero — это мегабайты и греющийся телефон ради впечатления,
которое клиент оценит один раз, а платить будет позициями в поиске. Если
эффект правда нужен под конкретный проект — обсуждать отдельно, а не ставить
«заодно».

Lottie отдельно: файл лёгкий, но нужен исходник из After Effects, а его никто
не рисует. Иконку в 20 строк SVG проще анимировать через CSS.

## Что анимировать по блокам

**Первый экран — не анимировать вовсе или анимировать только то, что не
текст.** Заголовок и главная картинка первого экрана — это LCP: если они
появляются скриптом из `opacity: 0`, метрика считается по моменту появления,
а при отвалившемся JS человек видит пустоту. Запрещено: `initial={{opacity:0}}`
на `<h1>`, класс `animate-fade-in` на hero-заголовке. Можно: плавный фон,
подъезжающая карточка сбоку, кнопка, которая отзывается на нажатие.

**Секции при прокрутке** — появление снизу вверх: `opacity 0→1` и
`translateY(16px→0)`, 300–400 мс, один раз (не повторять при обратной
прокрутке — от этого рябит). Список карточек — лесенкой по 60 мс, но не
больше пяти шагов: шестая карточка ждёт уже полсекунды и это заметно.

**Интерфейс** (кнопки, ссылки, поля, аккордеон) — 150–200 мс, `ease-out`.
Это не «анимация», это обратная связь; без неё сайт кажется мёртвым, и это
единственное место, где движение обязательно.

**Цифры и счётчики** — только если цифра настоящая (из карточки клиента, из
`clients/<домен>/`). Выдуманное «более 500 клиентов», которое ещё и
эффектно накручивается, ловится скриптом `check-shablon.sh` как «стоп».

**Формы** — состояние отправки и результат. Заявка ушла в никуда без единого
признака жизни — самая дорогая потеря на сайте.

**Параллакс и pin** — на мобильном отключать (`ScrollTrigger.matchMedia` или
`(min-width: 768px)`). На телефоне это дёргается, ломает прокрутку и мешает
попасть в кнопку.

## Правила движения

- **Только `transform` и `opacity`.** Всё остальное (`width`, `height`, `top`,
  `margin`) заставляет браузер пересчитывать раскладку на каждом кадре.
  `transition: all` — тоже нет: под `all` рано или поздно попадает раскладка.
- **Смещение 8–24 px.** Приезд на 100 px читается как «сайт собирается»,
  а не как «блок появился».
- **150–250 мс интерфейс, 300–600 мс появление.** Дольше секунды — сайт
  кажется медленным, даже если он быстрый.
- **`ease-out` по умолчанию** (`cubic-bezier(.16,1,.3,1)` — хороший
  универсальный): быстро стартует, мягко тормозит.
- **Ничего не крутится вечно** в поле зрения. `animate-pulse`, `animate-bounce`,
  бесконечный градиент — телефон не спит, батарея садится, глаз цепляется.
  Исключение — индикатор загрузки, пока она идёт.
- **`prefers-reduced-motion` обязателен.** Не вежливость: у части людей от
  движения кружится голова, и в России это ещё и вопрос доступности сайта.

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}
```

В React то же самое даёт `useReducedMotion()` из `motion/react` — им гасят
`initial`/`animate`, а не только CSS.

Готовые куски под каждый блок — в `references/dvizhenie.md`: сначала вариант
на голом CSS, рядом тот же приём на `motion`. Брать оттуда, а не сочинять.

## Проверка перед показом

```bash
.claude/skills/web-animation/scripts/check-anim.sh <папка сайта>
```

Уровень «стоп» (выход 1) — тяжёлая 3D-библиотека, две библиотеки анимации
разом, анимация на заголовке первого экрана, анимация без
`prefers-reduced-motion`. Уровень «внимание» — вечные циклы, длинные
длительности, `transition: all`, параллакс без мобильного отключения: выход
не меняет, решает человек.

Скрипт смотрит текст, а не поведение. Поэтому дальше — глазами: открыть
плагином `playwright` на узком экране, прокрутить до конца, посмотреть
консоль. И `/core-web-vitals` с `/web-quality-audit` — CLS и INP ломает
именно анимация, и ломает молча.

## Когда анимации быть не должно

Прототип к первому звонку (блоки 1–4 из `/lovable-site`) собирается **без
анимации**. Владельцу нужно показать вид и содержание за 30 секунд разговора,
а не ждать, пока секции приедут. Движение добавляется на боевом сайте, когда
структура уже согласована и переделка не спишет кредиты Lovable.
