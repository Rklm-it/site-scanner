# Скилы: дизайнерские инструкции для Клода

Скил — это папка с `SKILL.md`, которую Клод подхватывает сам, когда задача
похожа на описанную во фронт-маттере. От CLAUDE.md отличается тем, что тело
скила грузится только в момент применения: длинную методичку можно держать
рядом с проектом, и она ничего не стоит, пока не понадобилась.

## Что подключено

**`frontend-design`** — как делать сайт, который не выглядит сгенерированным.
Заставляет сначала выписать план (палитра из 4–6 названных цветов, пара
шрифтов, схема раскладки, один «фирменный» элемент), проверить его на
шаблонность и только потом писать код. Отдельно перечислены три вида, к
которым скатывается любая нейросеть (кремовый фон с серифом и терракотой;
почти чёрный фон с кислотным акцентом; «газетная» вёрстка с волосяными
линейками) — их велено не брать, если бриф прямо не просит.

Это ровно то, чего не хватало в промптах для Lovable: прототипы клиентов
собираются быстрее, чем придумывается их вид, и без такой инструкции все
получаются на одно лицо.

**`theme-factory`** — десять готовых тем (палитра + пара шрифтов) и правила,
как собрать свою. Полезно как быстрый ответ на «покажите варианты»: тему
выбираем с владельцем, а дальше её значения уходят в промпт Lovable или прямо
в CSS прототипа.

## Как это включается

Никак — скилы из `.claude/skills/` в репозитории подхватываются
автоматически: и в терминале, и в веб-сессиях Claude Code, потому что там
репозиторий клонируется целиком. Позвать явно — `/frontend-design`.

Где эти папки **не** работают: чат на claude.ai и Cowork читают скилы,
включённые в аккаунте, а не в репозитории. Там те же скилы надо включать
через настройки аккаунта на claude.ai.

## Откуда взято и как обновить

Источник — <https://github.com/anthropics/skills>, коммит `3b3fad9`
(21.08.2026), лицензия Apache 2.0, файлы `LICENSE.txt` внутри каждой папки
трогать нельзя. Копии не изменены; если начнём править под себя — сверху в
`SKILL.md` дописать, что именно поменяли (этого требует лицензия).

Обновить или добавить ещё один скил:

```bash
git clone --depth 1 https://github.com/anthropics/skills.git /tmp/anthropic-skills
cp -r /tmp/anthropic-skills/skills/<имя> .claude/skills/
```

Что там ещё есть, кроме взятого: `webapp-testing` (Playwright: прокликать
свою страницу и снять скриншоты — в образе Chromium уже стоит),
`web-artifacts-builder` (React + Tailwind + shadcn в один HTML),
`canvas-design` (постеры и PDF, 5,6 МБ шрифтов), `algorithmic-art`,
`skill-creator`, `mcp-builder`, `brand-guidelines` (фирстиль самой Anthropic —
нам не нужен), `docx`/`pdf`/`pptx`/`xlsx`.

## Почему копией, а не плагином

Второй способ — прописать маркетплейс в `.claude/settings.json`:

```json
{
  "extraKnownMarketplaces": {
    "anthropic-agent-skills": {
      "source": { "source": "github", "repo": "anthropics/skills" }
    }
  },
  "enabledPlugins": { "example-skills@anthropic-agent-skills": true }
}
```

Так скилы сами обновляются, но ставятся все двенадцать пачкой (включая
ненужные нам постеры на 5,6 МБ и генератор гифок для Слака), тянутся из сети
в начале каждой сессии и требуют доверия к папке. Копия в репозитории
предсказуемее и работает без сети — а обновляется одной командой выше.

## Свой скил студии

Самое ценное здесь — не чужие файлы, а возможность положить рядом свой:
`.claude/skills/<имя>/SKILL.md` с фронт-маттером `name` и `description`.
Напрашивается скил «как мы делаем редизайн»: типовые блоки лендинга под малый
бизнес, что писать в промпт Lovable, чем заканчивать страницу, какие следы
конструктора снимать перед показом. Сейчас это разбросано по `clients/СХЕМА.md`
и `deploy/prototype/README.md` и каждый раз перечитывается целиком.
