# Плагины: инструменты, которые ставятся вместе со скилами

Здесь лежат плагины маркетплейса `rklm` — того же, из которого раздаются скилы
студии. Скил объясняет Клоду, **как** делать; плагин из этой папки даёт
**чем**: подключает внешний MCP-сервер с инструментами.

| Плагин | Что даёт | Подробности |
|---|---|---|
| `playwright@rklm` | браузер: открыть, прокликать, скриншот, консоль | [playwright/README.md](playwright/README.md) |
| `context7@rklm` | свежая документация библиотек по запросу | [context7/README.md](context7/README.md) |
| `studio@rklm` | скилы студии (лежат в `.claude/skills/`) | [../.claude/skills/README.md](../.claude/skills/README.md) |

## Как включить

На машине разом (мак владельца, сервер) — тем же скриптом, что и раньше, он
теперь включает все три:

```bash
./tools/setup-machine.sh
```

В репозитории клиента (нужно для веб-сессий, настройки машины они не видят):

```bash
./tools/new-client.sh <путь к репозиторию клиента>
```

Проверить: `/mcp` показывает `playwright` и `context7`, `/skills` — `studio`.

Выключить один из них, не трогая остальные: в `~/.claude/settings.json`
поставить `false` у нужной строки в `enabledPlugins`.

Сам сканер настроен отдельно — `.claude/settings.json` в репозитории. Это ради
веб-сессий: настроек машины они не видят, а репозиторий клонируют целиком, и
без этого файла в браузерной сессии на сканере плагинов не было вовсе. `studio`
там сознательно не включён: скилы и так лежат в `.claude/skills/` и грузятся
напрямую, а через плагин приехала бы вторая копия.

## Чтобы сессия про них вспомнила

Включить инструмент мало: сессия, которая про него не вспомнила, ничем не
отличается от сессии без инструмента. Поэтому список печатается в контекст
хуком `SessionStart` — `.claude/hooks/session-start.sh`. Он раздаётся плагином
`studio` (`hooks/hooks.json`), значит работает и в репозиториях клиентов, и
продублирован в настройках сканера для веб-сессий.

Хук говорит три вещи: спросить документацию через context7 до правки кода по
библиотеке, посмотреть свою страницу через playwright после правки, и с чего
начинать сайт клиента. Отдельной строкой — что делать, если инструмента нет
(нет `npx`, пустой `/mcp`): сказать и пойти запасным путём, а не угадать.

Если включены оба пути сразу, хук срабатывает дважды — второй раз он молчит по
метке с `session_id` в `$TMPDIR`. Две одинаковые простыни в начале контекста
только мешают читать.

Проверено вживую: `claude -p` в пустой папке с включённым `studio` отвечает,
что ему сказали про context7, playwright и скилы.

## Чего эти плагины не дают

**Claude Desktop и Cowork их не увидят** — они читают то, что включено в
аккаунте claude.ai, а не в репозитории. Владельцу для чата на claude.ai:
Context7 есть в каталоге коннекторов, подключается там; браузер в чате не
заводится вовсе, для этого нужна сессия Claude Code.

Обоим серверам нужен **Node.js на машине** (запускаются через `npx`) и сеть до
npm. Внутри контейнера сканера они не работают и не нужны: там Клод не живёт.

## Почему отдельными плагинами, а не одним

Скилы включаются даром — тело грузится, только когда задача похожа. MCP-сервер
стоит дороже: это процесс, который стартует с сессией, и его описания
инструментов лежат в контексте всегда. Поэтому браузер и документация вынесены
из `studio` в свои плагины: в сессии, где нужен только разбор лида, их можно
выключить, не потеряв скилы.
