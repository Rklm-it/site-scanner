# «Выкладка» — приложение для macOS

Положил архив со сборкой сайта — он уехал на VPS, домен прописался в Caddy,
сертификат выпустился, и дальше видно, кто на сайт заходил. Обновление,
откат и удаление — оттуда же.

Работает с **сервером прототипов** (`/root/site-scanner`, Caddy,
`/root/prototypes-static`). Сервер сканера (`/root/site-scanner-main`) тут ни
при чём: Caddy прототипов на нём нет. Адрес подключённой машины приложение
всегда показывает в левом верхнем углу — обе машины отвечают на ssh
одинаково, и это единственный способ не перепутать.

## Собрать

Нужны инструменты командной строки Xcode (один раз: `xcode-select --install`).
Полного Xcode не требуется.

**На маке:**

```bash
cd ~/site-scanner/macos/Vykladka
./sobrat.sh
open "Выкладка.app"
```

Скрипт собирает SwiftPM-пакет, складывает `Выкладка.app` рядом и подписывает
её «для себя». Сторонних зависимостей нет: всё, что нужно для SSH, уже есть в
macOS — `/usr/bin/ssh`, `ssh-keygen`, `tar`.

## Первый запуск

Три шага в окне подключения:

1. **Адрес.** IP или имя сервера прототипов, пользователь (обычно `root`).
2. **Отпечаток.** Приложение спрашивает у сервера его ключ и показывает
   отпечаток. Сверьте с тем, что печатает сам сервер:

   **на сервере прототипов:**

   ```bash
   cd /root
   ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
   ```

   Совпало — подтверждаете. Дальше приложение подключается только к этому
   ключу; сменился — отказ, а не вопрос «продолжить?».
3. **Пароль — один раз.** Приложение заводит себе ключ ed25519, кладёт
   публичную половину в `~/.ssh/authorized_keys` на сервере, приватную — в
   Связку ключей macOS, и **пароль забывает**: он не сохраняется ни в
   настройках, ни в Связке, ни в файле.

После этого вход по паролю на сервере можно выключить совсем
(`PasswordAuthentication no` в `/etc/ssh/sshd_config`) — в логах видно, что в
`root` по паролю ломятся круглосуточно.

Если сервер уже настроен на «только ключи», третий шаг не пройдёт — пароль
там просто не примут. Тогда положите публичный ключ в `authorized_keys`
руками: он лежит в `~/.vykladka/id_ed25519.pub`.

Ключ и `known_hosts` лежат отдельно от остальных данных приложения, в пути
**без пробелов**, и это не придирка: значение `UserKnownHostsFile` ssh
разбирает как список файлов через пробел, поэтому путь внутри
«Application Support» распадается надвое и ssh отвечает «No ED25519 host key
is known … Host key verification failed» — при том что файл записан и лежит на
месте.

**Связка спросит разрешение** при первом обращении после каждой пересборки
приложения — потому что подпись «для себя» меняется с каждым билдом. Жмите
«Всегда разрешать».

## Что оно делает

**Кладёт сайт.** Перетащили `.zip`, `.tar.gz` или папку — приложение
распаковывает у себя, находит `index.html`, считает файлы и размер, смотрит
папки верхнего уровня и **ищет следы Lovable**. Нашлись — выкладка
блокируется, пока не подтвердите отдельно: клиент смотрит на сайт своей
компании, а не на витрину конструктора, и пересборка возвращает бейдж
обратно, поэтому проверка идёт перед каждой выкладкой.

**Заливает не поверх живого.** Архив распаковывается в соседнюю папку
`<имя>.novoe`, и только потом переименованием встаёт на место. Иначе полминуты,
пока идёт распаковка, клиент видел бы наполовину собранный сайт. Предыдущая
версия остаётся рядом как `<имя>.staroe` — это и есть откат в одну кнопку.

**Прописывает домен.** Блок Caddy пишется в `/root/caddy-sites/<имя>.caddy`,
конфиг проверяется `caddy validate` **до** перезагрузки, и только потом
`caddy reload`. Не собрался — блок возвращается как был: сломанный конфиг
гасит все сайты сразу, а не только новый.

Список путей, которые отдаются как файлы, строится из реальных папок архива.
Это не косметика: если ловить всё общим `try_files`, промах по картинке
вернёт `index.html` с кодом 200, а правило кэширования пометит эту разметку
«хранить неделю». На `mebel-ryazane` так и вышло — после выкладки фотографий
их неделю не было видно.

**Проверяет A-запись до того, как заводить домен.** Caddy, увидев новый
домен, сразу идёт за сертификатом. Если запись ещё не проставлена или ведёт
не туда, выпуск не пройдёт, а повторы упрутся в недельный лимит Let's
Encrypt — и домен нельзя будет включить, даже когда DNS почините.

**Показывает состояние**: код ответа и время ответа (проверяется с мака, а не
с сервера — сервер всегда ответит сам себе), сколько дней осталось
сертификату, размер папки на сервере, свободное место, жив ли контейнер Caddy.

**Показывает, кто заходил.** Читается лог Caddy: время, адрес, страницы,
устройство и браузер, откуда пришли. Ничего не добавляется на страницу
клиента — ни счётчика, ни куки, ни лишнего килобайта.

## Про посещения — что там честно, а что приблизительно

**Превью мессенджеров считаются отдельно, и это главное.** Отправили ссылку в
WhatsApp или Telegram — их робот открывает её через секунду. Без разделения
это выглядит как «клиент посмотрел сразу», а он ещё даже не открыл
переписку. Роботы поисковиков и сканеры — третья вкладка.

**«Тот же посетитель» — это адрес плюс браузер**, перерыв больше получаса
считается новым заходом. Куки нет и не будет, поэтому телефон,
переключившийся с wi-fi на мобильный, посчитается дважды. Точнее без счётчика
на странице не выйдет, а счётчик на странице клиента нам не нужен.

**Страна** — офлайн по бесплатной базе DB-IP, кнопка в настройках качает её на
мак; адреса посетителей никуда не отправляются. **Города в бесплатной базе
нет** — вместо него показывается обратное имя адреса, у российских
провайдеров в нём обычно виден и оператор, и город.

История хранится на маке в
`~/Library/Application Support/Vykladka/poseshcheniya.sqlite`. На сервере лог
ротируется по 5 МБ и старое затирается, а здесь остаётся всё — в том числе по
сайтам, которые давно убрали.

## Чего оно не делает

- **Не собирает проект.** Сборка идёт на маке, на сервер уезжает результат:
  VPS этого тарифа — 961 МБ, `bun run build` там получает SIGKILL от
  OOM-killer после ~13 минут свопинга.
- **Не заменяет `sync.sh`.** У части клиентов выкладка идёт из ветки `deploy`
  в GitHub — это по-прежнему `deploy/prototype/sync.sh` на сервере. Блоки
  Caddy у обоих путей одинаковые, они не мешают друг другу.
- **Не трогает чужие блоки.** Файл без метки `# vykladka:` показывается в
  списке, но не меняется и не удаляется: его завёл человек.
- **Не снимает A-запись** у регистратора при удалении сайта — это руками.
- **Не удаляет лог** удалённого сайта: это единственная история по нему на
  сервере, а весит она мегабайты.

## Что где лежит

| | |
|---|---|
| настройки, база посещений, база стран | `~/Library/Application Support/Vykladka/` |
| ключ и known_hosts | `~/.vykladka/` |
| сайты на сервере | `/root/prototypes-static/<имя>` |
| предыдущая версия | `/root/prototypes-static/<имя>.staroe` |
| блоки Caddy | `/root/caddy-sites/<имя>.caddy` |
| логи посещений | `/root/caddy-logs/<имя>.log` |

Первый раз каталоги на сервере заводит `deploy/prototype/install-sites.sh` —
см. `deploy/prototype/README.md`.

## Состояние

Конфиги Caddy (базовый и генерируемый приложением) проверены настоящим
`caddy validate` 2.8.4. Переезд блоков в каталог выполнен на живом сервере:
пять доменов отвечают `200`, логи пишутся, формат разбора сверен с настоящей
строкой лога. Приложение собирается на macOS без предупреждений
(`swift build`, ~48 секунд).
