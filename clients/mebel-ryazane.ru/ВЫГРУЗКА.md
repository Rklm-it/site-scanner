# Отчёт по выгрузке mebel-ryazane.ru

Выгрузка от **27.08.2026, 12:49**. Параметры: 1500 страниц, глубина 5,
50 минут, по карте сайта, robots.txt **игнорировали**.

Итог: **страниц 89, файлов 0, архив 6,1 МБ**.

## Что в этом хорошего

**Сайт скачан весь.** Ни один лимит не упёрся: в итоге нет строки «не
добрано», значит обход закончился сам. 89 страниц — это и есть сайт целиком,
каким его видит обход, а не обрезанный кусок.

**Заголовок главной сходится с ожиданием**: «Мебель на заказ Рязань недорого
по индивидуальному проекту». Домен набран верно, скачан тот сайт.

**Тексты внутри есть.** 6,1 МБ на 89 страниц — это ~70 КБ разметки на
страницу. Столько весит обычная серверная страница с содержимым; у сайта,
который рисуется скриптом, страницы приезжают пустыми обёртками по 2–5 КБ.
Это предположение по весу, а не факт: подтвердится, когда архив ляжет в
репозиторий.

## Что в этом плохого

**Ноль файлов — это ноль фотографий.** Не «выгрузка без оформления», а
выгрузка без товара: у мебельщика портфолио и есть предмет продажи. Ни
разобрать, что они делают, ни собрать прототип по этому архиву нельзя.

**Интерфейс дал неверный совет.** На ноль файлов он писал «обычно это
robots.txt закрывает папку с изображениями — снимите галочку и повторите»,
хотя галочка была уже снята и в той же строке написано «robots.txt
игнорировали». Второй заход с той же галочкой дал бы тот же ноль. Совет
исправлен: теперь при снятой галочке интерфейс показывает посчитанную обходом
причину, а не догадку.

## Причина найдена: сайт собран на конструкторе LPgenerator

Диагностика по готовому архиву (`tools/dump-kartinki.py`, выполнена владельцем
на сервере 27 августа) дала однозначный ответ:

```
Страниц разобрано: 88, адресов картинок в разметке: 23460
Из них своих и скачиваемых обходом: 0

   23315  media.lpgenerator.ru  ← https://media.lpgenerator.ru/images/276267/plan.jpg#size_594x376
      86  mc.yandex.ru          ← https://mc.yandex.ru/watch/52579810
      59  i.ibb.co              ← https://i.ibb.co/PC56vGV/png-transparent.png
```

**Ни одной картинки на собственном домене.** Сайт сделан в **LPgenerator** —
конструкторе лендингов; страницы отдаются на домене клиента, а всё содержимое
лежит на его CDN. Для обхода это чужой сайт, поэтому файлов приехало ноль.

Что из этих трёх строк следует по делу:

- **`media.lpgenerator.ru` — портфолио клиента.** Картинки достаются обычным
  запросом, антибота там нет: это не «Пульс цен» с `rgz61.ru`, где выгрузка
  была невозможна в принципе. Обход исправлен и теперь их забирает.
- **`mc.yandex.ru/watch/52579810` — у них стоит Яндекс.Метрика**, счётчик
  `52579810`. Значит есть история по заходам и заявкам. Попросить у клиента
  гостевой доступ: переделка вслепую и переделка с цифрами по трафику — два
  разных разговора, а после переезда Метрика ещё и покажет, не просели ли
  позиции.
- **`i.ibb.co` — часть картинок лежит на бесплатном файлохостинге imgbb**
  (59 упоминаний). Такие ссылки живут ровно до тех пор, пока хостинг их
  держит, и не принадлежат клиенту вовсе. Забрать сейчас, пока отдаются.

Отдельно: **23460 упоминаний — это не 23460 файлов.** В шаблоне конструктора
одна и та же картинка стоит на каждой странице, а `#size_594x376` в конце
адреса — способ LPgenerator просить нужный размер, файл за ними один. Сколько
получится уникальных — печатает та же команда после `git pull` (строка «Всего
уникальных картинок к скачиванию»). От этого числа зависит время перевыгрузки
и то, влезет ли выгрузка в репозиторий или её придётся разбирать на сервере,
как `papinalavka.ru`.

## Что это значит для разговора с клиентом

Сайт **не принадлежит клиенту целиком**: он арендует платформу и платит за
неё абонентскую плату, а фотографии его работ лежат на чужом сервере. Это тот
же аргумент, что и на `rgz61.ru` с «Пульс цен», только мягче: домен, судя по
адресу, всё-таки их собственный — **проверить прямым вопросом**, потому что
на конструкторах домен нередко оформлен на подрядчика.

Что отсюда честно продаётся: свой сайт вместо аренды, свои фотографии на
своём хостинге, отсутствие ежемесячного платежа за конструктор. Чего обещать
нельзя, пока не увидели цифры: рост заявок.

## Почему картинок нет: разбор кода обхода

Обход собирал адреса файлов ровно из четырёх мест разметки: `a href`,
`link href`, `img src`, `script src` — плюс `url(...)` из скачанных css.
Мимо проходило три случая, и все три на сегодняшних сайтах обычные:

1. **Ленивая загрузка.** Адрес лежит в `data-src` (или `data-original`,
   `data-lazy-src`), а в `src` — прозрачная заглушка `data:image/gif`. Так
   работает любая галерея на jQuery и половина шаблонов на Битриксе.
   Каталог мебели — это как раз галерея.
2. **`srcset` и `<picture>`.** Адреса под разные экраны в `srcset`, в `src`
   иногда нет ничего.
3. **Фон в атрибуте `style`** и в `<style>` на самой странице:
   `style="background-image:url(...)"` — так подключают первый экран и
   плитки разделов.

Плюс две причины, которые от разметки не зависят: картинки лежат **на чужом
хосте** (поддомен вида `st.` или CDN — для обхода это другой сайт) и **адрес
без расширения**, когда картинку отдаёт скрипт (`/thumb.php?id=7`).

Какая из пяти сработала здесь — по одной цифре «файлов 0» не определить, а
проверить с моей стороны нельзя: песочница в российские домены не ходит.
Поэтому причина теперь считается самим обходом и **едет в архиве**.

## Что исправлено в сканере

- `scanner/mirror.py` собирает адреса картинок из `data-*`-атрибутов,
  `srcset`, `<source>`, атрибута `style` и блоков `<style>`.
- **Картинки с чужих хостов теперь скачиваются** и ложатся в `_vneshnie/<хост>/`
  внутри архива — иначе сайт на любом конструкторе (LPgenerator, Тильда,
  uCoz) приезжает без единой фотографии. Стили и скрипты с чужих хостов
  по-прежнему мимо: чужое оформление в разборе не нужно, а архив раздувает.
  Отключается флагом `external_images=False`.
- К чужому CDN обход ходит чаще (0,25 с вместо 0,7): пауза придумана для
  самописного сайта на слабом хостинге, а 23 тысячи адресов по 0,7 с в бюджет
  не уложились бы.
- В `manifest.json` добавлены `asset_refs` (сколько адресов картинок
  встретилось в разметке) и `asset_skipped` (причина → сколько). Ноль
  картинок больше не немой: в архиве написано, куда они ведут.
- В очередь файлов больше не попадает HTML: страница-заглушка не сохраняется
  под видом скачанного файла.
- Подсказка в интерфейсе разделена на два случая — robots уважали и robots
  игнорировали.
- `tools/dump-kartinki.py` — разбор **уже сделанной** выгрузки: по какому
  хосту лежат картинки и почему не поехали. Перевыгружать для диагностики не
  надо.

Тесты: `tests/test_mirror.py`, два новых — ленивые картинки и запись причины
отказа. Весь набор проходит (226).

## Что сделать владельцу

Всё — на **сервере сканера**, из `/root/site-scanner-main`.

**1. Узнать причину по архиву, который уже лежит на томе** (перевыгрузка не
нужна, минута времени):

```bash
cd /root/site-scanner-main
git fetch origin claude/furniture-site-export-report-o9uh3o
git checkout claude/furniture-site-export-report-o9uh3o
docker compose exec app ls -la /data/webapp_data/dumps/
docker compose exec -T app python - /data/webapp_data/dumps/mebel-ryazane.ru-2026-08-27-1249.zip \
    < tools/dump-kartinki.py
```

Имя архива взять из `ls` — дата в нём своя. После слияния ветки в `main`
хватит обычного `git pull`.

Скрипт **самостоятельный**: из зависимостей только BeautifulSoup, `scanner` не
импортируется. Поэтому он работает и в контейнере, собранном из старого кода, —
пересобирать образ ради диагностики не надо. Вывод пришлите целиком: по нему
видно, докачиваются картинки обходом или съёмку придётся просить у клиента.

**2. Перевыгрузить с исправленным обходом** (сначала посмотреть в выводе
шага 1 строку «Всего уникальных картинок к скачиванию» — по ней видно, хватит
ли 50 минут; при 0,25 с на файл это примерно 250 картинок в минуту):

```bash
cd /root/site-scanner-main && docker compose up -d --build
```

(на ветке из шага 1; после слияния в `main` — `git pull` и та же команда)

Дальше вкладка «📦 Выгрузки»: `mebel-ryazane.ru`, галочку robots.txt снять
(клиент сам просит переделку), «по карте сайта» оставить, минут — 50.

**3. Положить выгрузку в репозиторий** — без этого разбора не будет, архив в
переписке следующая сессия не увидит:

```bash
cd /root/site-scanner-main
D=mebel-ryazane.ru
docker compose exec app ls -la /data/webapp_data/dumps/
docker compose cp app:/data/webapp_data/dumps/$D-ДАТА.zip /tmp/$D.zip
mkdir -p clients/$D/full && unzip -q -o /tmp/$D.zip -d clients/$D/full
git add clients/$D && git commit -m "Выгрузка $D для разбора" && git push
```

## Чего в этом отчёте нет и почему

Разбор выгрузки — это шесть пунктов (`.claude/skills/lovable-site/references/`
`razbor-dampa.md`): карта страниц, услуги их формулировками, тексты и прайсы,
список фотографий, что нужно от бэкенда, структура адресов и мета-теги.

Ни один из них по картинке из интерфейса не делается: нужен сам архив в
`clients/mebel-ryazane.ru/full/`. Как он там окажется — шаг 3 выше. После
этого разбор занимает одну сессию и ложится сюда файлами.
