# rgz61.ru — новый клиент на разработку сайта

Состояние на 19 августа 2026. Сайт клиента ещё не выгружен — см. «Выгрузка».

## Что за сайт

Витрина на конструкторе **«Пульс цен»** с прикрученным своим доменом:
`A` ведёт на 89.108.119.171, `www` — CNAME на `site.pulscen.ru`. Содержимое,
позиции и прайс лежат в панели платформы, клиент платит за аренду витрины.

Для разговора это аргумент: сайт клиенту не принадлежит. Для нас — короткий
путь к данным: в кабинете Пульс цен есть экспорт каталога, и он даст тексты
и цены в структурированном виде, без выковыривания из HTML.

## Выгрузка: обходом не берётся

Сайт закрыт поведенческой проверкой платформы — `503` со страницей
«Проверка безопасности — Pulscen» на все адреса, и с сервера, и по http, и
через www. Подробности и почему решатель проверки мы не пишем — в корневом
`CLAUDE.md`, раздел «Грабли».

Проверено с машины владельца: в Safari сайт открывается, а скрипту приходит
`503` на каждый из 400 адресов карты сайта — подряд, без единого исключения.
Значит проверка ловит **не адрес, а сам запрос**: браузер проходит, обход нет.

**Хуже того: после шестнадцати запросов подряд платформа пометила домашний
адрес владельца как нарушителя** — `403` с редиректом на
`?intruder_<хеш>=3`, и уже для любого заголовка, включая браузерный. Пометка
снимается сама за несколько часов, но каждый новый запрос продлевает счётчик.

**Не выгружать этот сайт вообще — ни с сервера, ни с мака.** Содержимое
берём из кабинета клиента. Карту сайта (400 адресов) отдаёт `sitemap.xml`
даже при 503 — её можно забрать **одним** запросом, когда блокировка спадёт;
она нужна для переадресации после переезда.

## Проект в Lovable — правим кодом

**Репозиторий: `Rklm-it/rostov-steel-forge`** (приватный), синхронизирован с
Lovable. Правки вносятся прямо в код и приезжают в Lovable сами — это
бесплатно и точнее промпта, кредиты тратить незачем.

Вся страница — один файл `src/routes/index.tsx`, секции отдельными
компонентами. TanStack Start + Tailwind 4, цвета заданы в `src/styles.css`
(`graphite`, `red`, `steel`, `light`). Проверять перед пушем:

```bash
bun install && npx tsc --noEmit && bunx eslint src/routes/index.tsx && bun run build
```

Сгенерированный Lovable файл линт проекта **не проходил** — 32 ошибки
prettier. Прогнан `bunx prettier --write`, дальше держать его чистым.

`bun run dev --port 5199 --host 127.0.0.1` — посмотреть глазами; без `--host`
падает на попытке слушать `::`.

**Палитра «горячий металл».** Акцент — янтарь `#D9761A`, на тёмном светлый
`#FFA94D`, графит `#14181C`, почти чёрный `#0C0E10`, светлый фон `#F3F4F6`.
Прошли через красный (тревожный, его было слишком много) и синий (строгий, но
пресный) — янтарь читается как искра из-под лазера и, в отличие от обоих,
держит тёмный фон. Токены в `src/styles.css` названы по роли (`accent`), а не
по цвету: имя должно пережить следующую смену палитры.

**Подача — тёмный цех, а не белый каталог.** Первый экран и секция
производства на чертёжной сетке (`blueprint`), светлые и тёмные секции
чередуются. Каталог разного калибра: две ходовые позиции крупными плитками.
Прайс — таблицей со стандартом и ценой, на телефоне карточками. Между первым
экраном и фактами едет лента номенклатуры (`marquee-track`, уважает
`prefers-reduced-motion`).

**Эталонный `prototype/index.html` — первая версия, для истории.** Источник
истины теперь проект в Lovable; HTML за ним не тянем, иначе разойдутся.

**Важно про порядок работы.** Пока правки идут кодом, в самом Lovable
страницу лучше не пересобирать промптами: он перепишет файл целиком и
изменения разойдутся.

### Выложить превью на сервер прототипов

Сборка идёт **вне сервера** (на VPS прототипов 961 МБ и OOM), результат лежит
в ветке `deploy` того же репозитория. Пересобрать её после правок:

```bash
cd /workspace/rostov-steel-forge
NITRO_PRESET=node-server bun run build          # cloudflare-пресет не годится
node .output/server/index.mjs &                  # снять готовую разметку
curl -s http://127.0.0.1:3000/ > /tmp/index.html
# следы Lovable: favicon и window.__lovable* в бандле — чистить обязательно
```

Дальше содержимое `.output/public` плюс снятый `index.html` уезжают в ветку
`deploy` принудительным пушем, а на сервере:

```bash
cd /root/site-scanner/deploy/prototype
./sync.sh rgz61 https://github.com/Rklm-it/rostov-steel-forge.git
```

Блок `rgz61.nexus-flow.ru` в `Caddyfile` уже есть — нужна только
A-запись поддомена на IP сервера прототипов.

## Домен: whois и DNS на 19.08.2026

```
registrar:   REGRU-RU              домен куплен через reg.ru
created:     2017-07-05            домену 9 лет — вес в поиске, адреса терять нельзя
paid-till:   2027-07-05            год в запасе
org:         (пусто)               оформлен на физлицо, не на ООО
state:       REGISTERED, DELEGATED, UNVERIFIED
nserver:     dns1/dns2.naunet.ru   зона НЕ в reg.ru и НЕ в Пульс цен
A            89.108.119.171        платформа
www          CNAME site.pulscen.ru
MX           нет                   почты на домене нет вообще
TXT          нет                   ни SPF, ни верификаций
```

**Ронять нечего** — обычный главный риск переезда (корпоративная почта) здесь
отсутствует, зона пустая. Меняются две записи.

**Но A-запись правится в панели naunet.ru**, а не у регистратора. Нет доступа
в Наунет — не тупик: владелец домена меняет NS в кабинете reg.ru на другие, и
зона переезжает туда. Для этого нужен доступ к reg.ru.

`UNVERIFIED` — контакты администратора не подтверждены. Регистратор вправе
снять домен с делегирования до верификации; клиенту стоит её пройти.

## Спросить у клиента

1. Доступ в кабинет **reg.ru** и на кого оформлен домен. Если на бывшего
   подрядчика или на сотрудника платформы — решать сейчас: перенос прав идёт
   письмом регистратору и занимает недели.
2. Доступ в панель **naunet.ru** — там сейчас правится DNS.
3. Доступ в кабинет **Пульс цен** — оттуда берём каталог с прайсом.

## Порядок переезда

1. Новый сайт на VPS, проверка по временному адресу.
2. За сутки понизить TTL в Наунете.
3. `A` → IP нашего сервера; `www` тоже `A` на наш IP вместо CNAME на
   `site.pulscen.ru`. Caddy выпустит сертификат сам, когда домен начнёт
   указывать на нас.
4. Проверить оба адреса после распространения.
5. **Только потом** клиент отключает Пульс цен. Отключит раньше — сайт
   пропадёт до переезда.

Старые адреса страниц сохранить или закрыть переадресацией: домену 9 лет, он
ранжируется, сломанные адреса стоят клиенту заказов. Список адресов даст
выгрузка.
