# Клиенты

Схема работы целиком — в `СХЕМА.md`, состояние по лидам — в `ЖУРНАЛ.md`.

Сюда складываем выгрузки сайтов, которые переделываем, и решения по каждому
клиенту. Всё, что здесь лежит, видит новая сессия — в отличие от переписки.

## Структура

```
clients/
  print-rf.ru/
    README.md      ← что за клиент, договорённости, цена, сроки
    dump/          ← выгрузка старого сайта
    prompts.md     ← промпты для Lovable по блокам
```

## Как выгрузить сайт клиента

**Вкладка «📦 Выгрузки» в интерфейсе.** Вписать домен, нажать «Выгрузить
сайт», дождаться, скачать zip и распаковать в `clients/домен.ru/full/`.

Раньше это делалось `wget --mirror` на сервере, и каждый раз всплывало одно и
то же: команда падала с `free(): invalid pointer` на конвертации ссылок,
тянулись десятки RSS-лент (`?format=feed`), а страницы в windows-1251
ложились в репозиторий нечитаемым мусором. Всё это разобрано в
`scanner/mirror.py` и больше руками не чинится.

Что выгрузка делает сама:

- не качает тяжёлое (архивы, PDF, видео, шрифты) и RSS-ленты;
- не заходит в админку, корзину и поиск — там нечего разбирать;
- приводит страницы к UTF-8, даже если сайт отдаёт windows-1251 без
  объявления;
- забирает картинки, подключённые только фоном из CSS, — на старых сайтах
  так сделана половина оформления;
- кладёт внутрь архива `manifest.json` с картой сайта: адрес, заголовок,
  `description` и размер каждой страницы. **Начинать разбор стоит с него.**

Ограничения по умолчанию: 150 страниц, глубина 3, 7 минут, 80 МБ. Если в
итоге написано «упёрлись в лимит» — поднять «Страниц» и повторить.

**Перед коммитом всё равно посмотрите, что внутри.** Отсев служебных путей
работает по списку известных CMS, а самописные админки называются как
попало.

Обход честно ждёт между запросами и по умолчанию уважает `robots.txt`.
Галочку снимать только для сайта клиента, который сам попросил его
переделать: на Joomla robots закрывает папки со стилями, и выгрузка выходит
без оформления.

## Что из выгрузки достаётся

Карта страниц (обычно из сорока нужны восемь), полный перечень услуг их же
формулировками, реальные тексты и прайсы, фотографии для переноса, структура
адресов и мета-теги — чтобы после переезда **не потерять позиции в поиске**.
Последнее особенно важно: старый сайт уже ранжируется, и сломанные адреса
стоят клиенту заказов.

## Выгрузка базы лидов

Срез для разбора в сессии — `выборка.py`. По ssh на сервере:

```bash
cd ~/site-scanner-main          # каталог с docker-compose.yml
git pull
docker compose exec -T app python - < clients/выборка.py --city Ростов
```

Скрипт скармливается питону через stdin намеренно: в образ копируются только
`scanner/` и `webapp/`, каталога `clients/` внутри контейнера нет. Через stdin
хватает `git pull`, пересобирать образ не нужно.

Что делает сверх сырого дампа: выкидывает лидов без телефона, с мусорным
телефоном, с заглушкой хостера вместо сайта, со свежим сайтом и тех, кого уже
трогали (по статусу из интерфейса, а не из json — там он на момент скана).
Причины отсева печатает числами — по ним видно, гнать ли новый скан.

Колонки, которых нет в сыром дампе и без которых уже наступали на грабли:

- **ИНН** — найден ли он на сайте. Пусто значит, что компания подтянута по
  названию, и оборот с директором могут быть от чужой фирмы;
- **дней** — возраст строки. База накопительная: лид мог быть отсканирован до
  очередной правки движка, и тогда его контактам верить нельзя. Проверка
  номеров, например, появилась только 6 августа 2026 (`ab7262f`);
- **рег** — регион по коду телефона: `863` наш, `моб`, `федер` (8-800) или
  `чужой:495`. Город в поисковом запросе к городу компании отношения не имеет:
  по запросу «Ростов» в базу приезжают Москва, Краснодар и Пермь;
- **орг** — `ЛИКВИД` капсом, если компания ликвидирована. В первом же срезе
  таких оказалось двое.

Проверка телефона берётся из движка (`contacts._plausible_phone`), а не пишется
заново: правило про коды 3/4/8/9 должно жить в одном месте.

Аргументы: `--limit N` (сколько строк, по умолчанию 60), `--city ТЕКСТ`,
`--min-outdated N` / `--max-outdated N` (окно балла старости, по умолчанию
40–100). Вывод — TSV, копируется в чат целиком.

Если нужен именно сырой дамп всех полей:

```bash
docker compose exec app python -c "
import json, sqlite3
c = sqlite3.connect('/data/webapp_data/leads.sqlite')
rows = c.execute('SELECT data FROM leads ORDER BY outreach_score DESC').fetchall()
F = ['priority','outreach_score','outdated_score','domain','company','revenue',
     'corp_email','marketing','emails','phones','cms','source_query']
print('\t'.join(F))
for (d,) in rows[:50]:
    r = json.loads(d)
    print('\t'.join(str(r.get(k,''))[:55] for k in F))
"
```

## Как читать лида перед звонком

**Берём**: сайт услуг (не магазин с каталогом), ООО с оборотом 10–100 млн,
корпоративная почта на своём домене, стоит Метрика или реклама, балл старости
45–65, местный бизнес.

**Пропускаем**: интернет-магазины с корзиной (переделка от 250к и свой
подрядчик), агрегаторы и порталы, ГУПы (тендеры и согласования), сайты не
вашего региона, ИП с низким чеком.

**Проверяем за тридцать секунд**: открыть сайт, поискать корзину и личный
кабинет (есть — мимо), убедиться, что телефон в шапке живой. И первым
вопросом в разговоре: «Сайт у вас основной, по нему работаете?» — после
случая, когда компания давно переехала на другой домен.

**Не доверяем карточке без ИНН.** Если ИНН на сайте не нашёлся, компания
подтянута по названию и может оказаться чужой — вместе с оборотом и
директором. Проверять до звонка.
