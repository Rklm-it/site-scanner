# textileopt.ru — «Текстиль-Сити», Ростов-на-Дону

Оптовый интернет-магазин товаров для швейного и мебельного производства:
ткани, фурнитура, наполнители, комплектующие для матрасов, швейное
оборудование, упаковка, домашний и гостиничный текстиль. Работают с 2009 года
(в 2020 на сайте висела новость «УРА!!! Мы 11 лет с Вами!!!»).

Разбор выгрузки `textileopt.ru-2026-09-01-0753` — 1 сентября 2026.
Что где лежит:

- **`КАРТА.md`** — карта сайта, дубли, хлам, мета-теги и адреса при переезде.
- **`КАТАЛОГ.md`** — дерево из 300 разделов и 662 карточки товара дословно.
- **`razbor.py`** — чем это собрано; пересчитать после дозагрузки выгрузки.

## Кому они продают

Пять сегментов, и все пять видны прямо в структуре каталога — это редкость и
это подарок для нового сайта:

1. **швейные производства** — ткани, фурнитура, нитки, иглы, оборудование;
2. **мебельные и матрасные производства** — комплектующие для матрасов,
   поролон, войлок, мебельные ткани, гобелен;
3. **отели и рестораны** — отдельный раздел «Текстиль для отелей»;
4. **детские сады** — отдельный раздел, то есть заходят и в госзакупки;
5. **розница** — отдельная страница `/retail/` и раздел «Домашний текстиль».

Новый сайт должен разводить их по входам с первого экрана. Сейчас на главной
один общий заголовок «Всё для швейного и мебельного производства», и отель с
детским садом в него не попадают вовсе.

## Контактов у нас пока нет

**Ни телефона, ни адреса, ни ИНН.** В `manifest.json` лежат только адреса
страниц и мета-теги, а страница `/contacts/` осталась внутри HTML, который
качается частями из релиза. Забрать их — первая команда в блоке ниже.

Пока контактов нет:

- **ИНН неизвестен**, юрлицо тоже. Оборот и директора не смотрели, в разговор
  подшивать нечего. Обогащение по названию не годится: DaData вернёт
  «похожее», и на `print-rf.ru` это уже привело к чужой карточке.
- **Звонить рано.**

## Что за сайт

1С-Битрикс, около **8300 страниц**, работающий магазин с корзиной,
регистрацией, личным кабинетом, умным фильтром и сравнением товаров. Обход
снял 1420 страниц и остановился по общему дедлайну — подробности и что это
значит для переезда в `КАРТА.md`.

## Аргументы к разговору

Все четыре взяты из выгрузки, ни один не выдуман. Первый — самый наглядный.

**1. Сайт про ткани рассказывает поиску про садовую технику.** У семи страниц
(`/info/`, «Вопрос-ответ», «Статьи», три статьи и политика конфиденциальности)
в `description` написано: «Мы предлагаем широкий ассортимент качественного
инструмента и **садовой техники** по адекватным ценам». У страницы «Гарантия
на товар» — оттуда же. Это хвост чужого шаблона, который никто не убрал.
Показывается за десять секунд и не требует никаких инструментов: открыть
страницу, `Ctrl+U`, найти `description`.

**2. Ещё у 22 страниц описание — заглушка Битрикса** «Оптимальный
интернет-магазин». Среди них все четыре акции и раздел «Акции» целиком, то
есть именно те страницы, которые должны приводить покупателей.

**3. Сайт живёт по двум адресам сразу** — `textileopt.ru` и
`www.textileopt.ru`, обе версии отдают содержимое. 341 страница из выгрузки
снята дважды. Для поиска это две копии магазина.

**4. Товары конкурируют сами с собой.** 38 карточек ниток имеют одинаковый
`title`, ещё 16 — «Тик пухо-перовой», 6 — «Батист принт». В выдачу не проходит
ни одна.

Что к этому **нельзя** добавлять, пока не проверено:

- **Скорость.** HTML одной страницы весит 280 КБ (медиана по 1043 страницам),
  это много — но вес разметки не то же самое, что скорость загрузки. Прежде
  чем говорить это клиенту, прогнать сайт через PageSpeed и показать цифру.
- **«Новостей нет с 2021 года».** Обход снял не все новости; самая свежая из
  снятых — 2025 год. Проверяется после дозагрузки.
- **Возраст дизайна.** Балл сканера по этому лиду мы не смотрели — лид в
  `ЖУРНАЛ.md` не заводился, пришёл помимо очереди звонков.

## Что дальше — команды владельцу

### Блок 1. Сервер сканера: свободное место и свежая ветка

```bash
cd /root/site-scanner-main
git fetch origin
git checkout -B claude/textileopt-new-client-i6zs6n origin/claude/textileopt-new-client-i6zs6n
docker compose exec -T app df -h /data | tail -1
docker compose exec -T app ls -la /data/webapp_data/dumps/
```

`/data` — том **внутри контейнера**, на хосте такого пути нет: без
`docker compose exec` обе команды падают с `No such file or directory`, и
выглядит это как поломка сервера.

Последняя строка — не для порядка. **В релизе лежат части 01, 02 и 04, а 03
нет.** Нумерация частей сквозная, пропусков в ней не бывает, значит часть 03
не уехала в GitHub. Если она осталась на томе — её видно этой командой, и её
надо доотправить или хотя бы разобрать на месте; если её нет нигде, часть
выгрузки потеряна и по этим страницам придётся идти вторым прогоном.

### Блок 2. Сервер сканера: тексты живых страниц (около 7 МБ на диск)

```bash
cd /root/site-scanner-main
docker compose exec -T app python - textileopt.ru-2026-09-01-0753 --tolko \
    'index.html' 'company*' 'info*' 'help*' 'payment*' 'delivery*' \
    'retail*' 'contacts*' 'services*' 'sale*' 'privacy-policy*' 'include*' \
    < tools/vzyat-vygruzku.py
docker compose exec -T app python - /data/razbor/textileopt.ru-2026-09-01-0753 \
    < tools/teksty-iz-vygruzki.py > clients/textileopt.ru/ТЕКСТЫ.md
wc -l clients/textileopt.ru/ТЕКСТЫ.md
```

Части качаются все (190 МБ), но каждая удаляется сразу после разбора, а на
диск ложатся только отобранные страницы: пик по месту — одна часть.

**Что в какой части лежит — выяснилось на этом прогоне:** страницы в частях 01
и 02 (26 и 30 подошедших файлов), в части 04 их нет вовсе — она целиком из
картинок. Значит **пропавшая часть 03 — это страницы каталога**, то есть ровно
те, откуда берутся цены. Пока она не найдена, блок 3 достанет цены только по
той части карточек, что попала в 01–02.

Отсюда приезжает то, чего сейчас не хватает совсем: телефоны, адрес склада,
режим работы, условия опта и доставки, дословный текст «О компании» и
«Услуги», вопросы-ответы. Без этого прототип не собирается — выдумывать в
промптах нельзя.

### Блок 3. Сервер сканера: цены (185 МБ на диск, только если место есть)

Смотреть на вывод `docker compose exec -T app df -h /data` из блока 1: **если
свободно меньше 400 МБ — не запускать**, сначала чистить (`docker image prune -f`, старые архивы на
томе).

```bash
cd /root/site-scanner-main
docker compose exec -T app python - textileopt.ru-2026-09-01-0753 --tolko 'catalog/*' \
    < tools/vzyat-vygruzku.py
docker compose exec -T app python - /data/razbor/textileopt.ru-2026-09-01-0753 --tovary \
    < tools/teksty-iz-vygruzki.py > clients/textileopt.ru/ЦЕНЫ.tsv
head -5 clients/textileopt.ru/ЦЕНЫ.tsv
docker compose exec -T app rm -rf /data/razbor/textileopt.ru-2026-09-01-0753/catalog
docker compose exec -T app df -h /data | tail -1
```

`head -5` — не украшение: разметку цен на этом сайте я не видел, скрипт ищет
её в трёх местах по очереди. Если в третьей колонке приехала не цена, это
чинится в `tools/teksty-iz-vygruzki.py`, а не подгонкой вывода.

### Блок 4. Отправить результат

```bash
cd /root/site-scanner-main
git add clients/textileopt.ru/
git commit -m "Тексты и цены textileopt.ru из выгрузки"
git push -u origin claude/textileopt-new-client-i6zs6n
```

## Что делаем после этого

По схеме: шаг 2 — `DESIGN.md` (одно громкое место, фирменный приём, кегли и
палитра числами), и только потом промпты для Lovable по блокам. Заготовка

данных, а что ждёт текстов и фотографий.

## Красные линии по этому клиенту

- **Цены не сочинять.** Пока `ЦЕНЫ.tsv` не приехал, в прототипе на месте цены
  стоит `[цена уточняется]`, а не число.
- **Обмен с 1С не обещать**, пока не увидели их 1С. Семь тысяч товаров руками
  не переносятся, и разговор про обмен — самая дорогая часть проекта. На
  `papinalavka.ru` подрядчик четыре года объясняется именно этим.
- **Адреса каталога сохранять один в один.** Восемь тысяч страниц уже
  ранжируются; карта переадресаций — в `КАРТА.md`.
- **Это магазин, а не лендинг.** Lovable соберёт витрину без корзины и
  личного кабинета. Продаём то, что показываем.
