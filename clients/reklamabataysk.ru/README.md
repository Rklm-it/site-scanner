## На что посмотреть первым делом

**402 КБ — очень мало.** Для сравнения `projekt-doma.ru` — 49 МБ и 108
страниц. Столько весит либо сайт-визитка в несколько страниц (тогда всё в
порядке), либо обход, которому не дали пройти дальше главной. Различаются
эти два случая по `manifest.json`:

- страниц мало, но у каждой свой заголовок и вес по 20–60 КБ — сайт
  действительно маленький;
- одна-две страницы, или страницы по 2 КБ — обход упёрся. Тогда по порядку:
  снять галочку «уважать robots.txt» и повторить (в рунете `User-agent: *`
  часто закрыт целиком), а если снова пусто — смотреть признаки сборки на
  скриптах (`__NEXT_DATA__`, `data-reactroot`, `window.wixapps`): обход не
  выполняет JavaScript.

И отдельно: сайт может оказаться **не клиентским**, а витриной на
конструкторе вместе с доменом — как `rgz61.ru` на «Пульс цен». Это видно по
разметке и меняет весь разговор: продавать тогда нужно не редизайн, а
собственный сайт.

## Как перенести выгрузку в репозиторий

Всё — из `/root/site-scanner-main` на сервере владельца, иначе
`docker compose` не найдёт конфигурацию. Качать zip браузером не нужно, он
уже лежит на томе:

```bash
D=reklamabataysk.ru
docker compose exec app ls -la /data/webapp_data/dumps/
docker compose cp app:/data/webapp_data/dumps/$D-2026-08-25-2132.zip /tmp/$D.zip
mkdir -p clients/$D/full && unzip -q -o /tmp/$D.zip -d clients/$D/full
head -c 2000 clients/$D/full/manifest.json
git add clients/$D && git commit -m "Выгрузка $D для разбора" && git push
```

Последняя строка перед коммитом — не формальность: отсев служебных путей
работает по списку известных CMS, а самописные админки называются как
попало.
